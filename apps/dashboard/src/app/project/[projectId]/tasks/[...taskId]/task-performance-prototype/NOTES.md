# Task Performance Prototype

## Question

How should one Task page explain current evidence, longitudinal reliability,
definition changes, execution revisions, and model comparisons without
collapsing them into one misleading all-history pass rate?

## Variants

- `pulse`: current evidence first, with summary metrics and a compact history.
- `timeline`: definition and execution boundaries are the primary structure.
- `matrix`: execution revisions and models form a controlled-comparison table.

All variants use the same fixture data and can switch between the current
published baseline and the complete history including an unpublished working
definition.
