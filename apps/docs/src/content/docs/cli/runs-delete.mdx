Sometimes the run is garbage, not the agent. The database was down, the environment pointed at staging, a dependency timed out, the harness failed, not the implementation under test. `apo runs delete` removes such runs permanently so lists, stats, and comparisons reflect real signal instead of infrastructure noise.

:::danger[Irreversible]
Deletion removes the run's checks, judgments, test-result corrections, deliverables (rows **and stored objects**), execution attempt, and trace. Nothing is kept. The parent batch's rollups are recomputed, and a batch emptied by deletion goes with it. There is no undo.
:::

## Synopsis

```bash
apo runs delete <run-id>... --yes
```

## Description

Takes one or more **run ids** (unique prefix or `last` works, like [`apo runs show`](/cli/runs-show/)). All ids are resolved before anything is deleted, so a typo in the third id never takes down the first two. Runs are then deleted sequentially; the command stops at the first failure.

`--yes` is **required**. Without it the command prints what *would* be deleted and exits with code `2`, no request is sent. This is the confirmation, deliberately non-interactive: the command never prompts, so it is safe for agents and CI.

```bash
apo runs delete run_de89cab0

run_de89cab0f1e2d3a4b5c6d7e8 would be deleted
Pass --yes to permanently delete — this cannot be undone.
```

Deleting a run keeps the batch honest: the batch's counters are recomputed from the surviving runs, and deleting the last run of a batch removes the (now meaningless) batch and its task revision bundles.

## Requirements

- **Project admin.** Deletion is destructive history rewrite; a member-role caller is refused. The same gate applies in the dashboard.
- **Terminal or cancelled runs only.** A `running`/`pending` run is refused with exit `2`, cancel it first (`apo batch show` links the batch; the dashboard has per-batch cancel).
- The demo workspace is read-only; its runs cannot be deleted.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | All requested runs deleted. |
| `2` | Missing `--yes`, usage error, or API failure, unknown run, still-active run, missing admin role, artifact-store cleanup failure (retryable; the run is kept). |

## Examples

```bash
# One garbage run by prefix
apo runs delete de89cab --yes

# The latest run (e.g. a smoke test that hit a dead dependency)
apo runs delete last --yes

# Several at once: all resolved before anything goes
apo runs delete run_aa1100 run_bb2200 run_cc3300 --yes
```
