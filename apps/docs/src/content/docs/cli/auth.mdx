## `apo login`

Authenticate with a backend and set the context **every** command uses: backend URL, account, project, and task root. The login is remembered per backend (`~/.apo/logins/`), so switching between backends (local dev ↔ a hosted server) is one command with no password.

### Synopsis

```bash
apo login [--email <addr> --password <pw> --project <id|name>] [--backend <url>] [--force]
```

### Description

Verifies any existing saved key against the backend first, so you don't get stuck "logged in" with a key that every command rejects. If the key is invalid or absent, prompts for backend URL, email, and a masked password, then lists your projects and asks which one to scope the key to.

A new key is minted server-side (`POST /v1/api-keys/bootstrap`) and scoped to the chosen project. The key is written to `~/.apo/credentials` (the **active** login) alongside the backend URL, project id, and task root, and the whole context is remembered under `~/.apo/logins/<backend>.json`.

The task root captured here is the universe [`apo task list`](/cli/task-list/) and [`apo task run`](/cli/task-run/) resolve against; pass `--dir` to set it explicitly at login time.

### Switching backends

```bash
apo login --backend http://localhost:8000
```

If a remembered login exists for that backend, it is verified and restored, no email, no password:

A remembered key the backend rejects (rotated, different database behind the same URL) falls through to normal email + password re-authentication. Logging into a new backend never destroys the old login, it stays remembered, and the success message tells you how to switch back.

:::caution[You need a project first]
`apo login` lists the projects your account can access and asks you to pick one. On a fresh backend with no projects yet, it exits with:

```text
This account has no projects yet.
  Run `apo project create <name> --email … --password …` to create one,
  then run `apo login` again.
```

The mint endpoint rejects any project id that has no `ProjectDB` row (a `404`), so you cannot log in against a project that doesn't exist. See [`apo project create`](/cli/project/).
:::

### Options

| Option | Default | Description |
|---|---|---|
| `--email <addr>` | (prompted) | Email to authenticate with. |
| `--password <pw>` | (prompted) | Password (masked at the prompt). |
| `--project <id\|name\|prefix>` | (prompted) | Project to scope the key to. Accepts an id, name, or unique prefix. If omitted and you have one project, it's auto-selected. |
| `--backend <url>` | (prompted) | Backend to log in against. Switches instantly when a remembered login exists for it (`APO_BACKEND_URL` works too). |
| `--force` | off | Re-authenticate even if a valid key is already saved. |

### Examples

```bash
# Interactive: prompts for everything
apo login

# Non-interactive (CI, scripts)
apo login --email sami@example.com --password '*****' --project acme-evals

# Force re-auth against a different backend
apo login --force --backend https://apo.internal.company.com
```

## `apo logout`

Sign out. Deletes the active credentials **and** the remembered login for that backend, a real sign-out leaves no valid API key on disk. (Switch backends with `apo login --backend` instead of logging out, switching keeps both logins.)

### Synopsis

```bash
apo logout
```

### Output

<TerminalOutput
  lines={[
    { text: "✓ Logged out (sami@example.com).", tone: "success" },
    { text: "  Removed: ~/.apo/credentials" },
  ]}
/>

If you weren't logged in, prints `Not logged in.`

## `apo profile`

Named connection contexts: save a whole login (backend, API key, project, task root) under a short name, then switch with one word. Where `apo login --backend` switches between backends, profiles switch between accounts, two profiles can share one backend with different accounts and projects.

### Synopsis

```bash
apo profile [list]           # list saved profiles (the default subcommand)
apo profile save <name>      # save the active login as a profile
apo profile use <name>       # switch the active context to a profile
apo profile remove <name>    # delete a profile (never touches the active credentials)
```

### Description

- **`save`** snapshots the current active login (backend, API key, project, task root) under `<name>`. Refuses to overwrite an existing profile unless `--force` is passed. With `--from-login <url>` it builds the profile from a remembered login for that backend instead of the active one, so you can profile a login you currently aren't using.
- **`use`** verifies the profile's key against the backend before switching. On failure the active credentials are left untouched, a broken profile can never log you out.
- Profiles are stored as `~/.apo/profiles/<name>.json`. `list` also shows the legacy per-backend remembered logins, the same ones `apo login --backend` switches between.

### Options

| Option | Default | Description |
|---|---|---|
| `--force` | off | (`save`) Overwrite an existing profile of the same name. |
| `--from-login <url>` | - | (`save`) Build the profile from the remembered login for this backend instead of the active one. |

### Examples

```bash
apo profile save prod
apo profile use prod
apo profile list
apo profile remove prod
```
