`apo status` answers "what will my commands actually talk to?" After [`apo login`](/cli/auth/), the whole context (backend, account, project, task root) lives in `~/.apo/credentials`, with one remembered login per backend in `~/.apo/logins/`. This command surfaces the active context, lists the remembered logins you can switch to, checks that the backend answers, and warns when the task root doesn't exist.

## Synopsis

```bash
apo status
```

No options beyond the globals. Resolution order matches every other command: flag > environment variable > `~/.apo/credentials` > default.

## When to run it

- **After `apo login` from a new machine or clone**: confirm the captured task root points where your tasks actually live; it is the universe `task list` and `task run` share.
- **When runs land in the wrong backend or project**: the printed Backend and Project are what every command will use; the Saved line shows the remembered logins one `apo login --backend <url>` away.
- **When the backend "disappears"**: the reachability marker distinguishes a wrong backend from a down server.

The task-root line prints a warning when the directory doesn't exist, that state means `apo task run` has nothing to resolve against.
