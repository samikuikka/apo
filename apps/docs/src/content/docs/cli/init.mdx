`apo init` finishes onboarding by handing the job to your own coding agent. It detects which coding agents are installed (Claude Code, Cursor, Codex CLI, Gemini CLI, OpenCode), installs the apo authoring skill where all of them can read it, and opens the one you pick pointed at a single task: **write an adapter and your first task for this repo.** The agent explores your real code and scaffolds against it — no templates to copy from docs.

## Synopsis

```bash
apo init [--agent <id>] [--no-launch]
```

| Flag | Meaning |
|---|---|
| `--agent <id>` | Launch this agent without the picker: `claude-code`, `cursor`, `codex-cli`, `gemini-cli`, `opencode`. |
| `--no-launch` | Install the skill only — no agent selection, no spawn. |

## What it does

1. **Detects** installed coding agents. A tool counts as detected when its binary is on `PATH` or one of its config directories exists (`~/.claude`, `.cursor`, …).
2. **Installs the apo authoring skill** into `~/.agents/skills/apo/` (Codex, Gemini, OpenCode, Cursor) and `~/.claude/skills/apo/` (Claude Code) — for **all** agents, regardless of which one you launch. The skill teaches the whole loop: adapter, task, checks, publish, run, repair.
3. **Launches** the selected agent in your project root with a kickoff prompt: set up apo, write the adapter and the first `*.eval.ts` task, publish, run, iterate to PASS. Claude Code opens with `--permission-mode acceptEdits` so it can write files; Cursor opens the project and you type `/apo` in the agent chat.

## After the launch

The kickoff prompt names the installed skill's path, so the agent always has a source for the authoring API. When the repo already carries `@apo-ai/sdk`, agents usually learn from the package's own types while exploring — the skill is the floor, not the ceiling.

:::caution[Fresh repo, login captured elsewhere]
A login remembers the task root it was created with. If your saved login points at another checkout, `apo task run <task-id>` fails here with *Task directory not found*. Pass the root explicitly — `apo task run <task-id> --dir ./e2e` — or run `apo login` again in this repo to capture its task root.
:::

## Ownership rules

- A skill directory the CLI installed carries a marker file; re-running `apo init` updates those in place.
- A hand-installed apo skill (no marker) or a **symlink** is reported and **left untouched** — the CLI never deletes what it didn't write.

## When to run it

- **After `apo login`**, in the repository that holds the agent you want to test. Login isn't required to install the skill, but the launched agent needs it before it can publish or run tasks — init says so if it's missing.
- **Headless / scripted**: the picker picks the detected agent but nothing spawns without a terminal; pass `--agent <id>` explicitly to launch for real.
