Show a task's details, adapter, checks, and how it has been performing. With a backend project, the task comes from the synced catalog and includes its display name, tags, run stats (total · passed · failed · errored · pass rate · avg duration), and the latest run. Comes from the task root your login captured, the same universe as [`apo task list`](/cli/task-list/) and [`apo task run`](/cli/task-run/). `--catalog` looks it up in the backend's published inventory instead; an explicit `--dir` scans a specific directory.

## Synopsis

```bash
apo task show <task-id>
```

## Options

| Option | Default | Description |
|---|---|---|
| `<task-id>` | (required) | Task id (folder name). |

## Output

With a backend project, the task comes from the synced inventory and includes the latest run:

<TerminalOutput
  lines={[
    { text: "Task: real-agent/documents/document-qa" },
    { text: "  Name:        document-qa" },
    { text: "  Adapter:     realAgentAdapter" },
    { text: "  Checks:      yes" },
    { text: "  Path:        real-agent/documents/document-qa" },
    { text: "  Folder:      real-agent/documents" },
    { text: "  Runs:        5 total · 2 passed · 2 failed · 1 errored (40% pass) · avg 6.4s" },
    { text: "  Latest run:  run_de89cab0f1e2d3a4b5c6d7e8 — failed", tone: "danger" },
  ]}
/>

`Checks` is a `yes`/`no` flag. The `Latest run:` line (when one exists) gives the run id and its status.

Without a backend project, the task is read from the local filesystem, it shows `Deliverables:` (comma-joined) and a `Files:` list instead, and no latest run:

  lines={[

    { text: "  Files:", tone: "default" },
    { text: "    - contract.pdf", tone: "default" },
  ]}
/>
