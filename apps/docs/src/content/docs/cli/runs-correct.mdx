Sometimes the eval is wrong, not the agent. `apo runs correct` records a human decision about one recorded top-level test: set its **effective** result to PASS or FAIL, or restore the recorded result. The Check Report, assertions, judge responses, and judgments stay untouched machine evidence, a correction is interpretation after execution, never a rewrite of it.

## Synopsis

```bash
apo runs correct <run-id> <test-id> (--pass | --fail | --clear) [--reason <text>] [--task <id>]
```

## Description

Takes a **run id** (unique prefix or `last` works, like [`apo runs show`](/cli/runs-show/)) and the exact **test id** of one recorded top-level test. Exactly one action flag is required:

- `--pass`, the test's effective result becomes PASS
- `--fail`, the effective result becomes FAIL
- `--clear`, removes the active correction; the recorded result is effective again

`--reason` is **required** for `--pass`/`--fail` (3–1000 characters, trimmed) and recorded with the correction. `--clear` needs no reason. The command never prompts or opens an editor, it is safe for agents and CI.

The effective result is what every current surface uses: run and batch verdicts, lists, stats, comparisons created after the correction, the dashboard, and `apo runs show --exit-status`. Re-running the same correction with the same reason is an idempotent success, no duplicate row is appended.

## What a correction is not

- **Not a rejudge.** [`apo runs rejudge`](/cli/runs-rejudge/) produces a new *machine* judgment by replaying the eval; a correction records a *human* decision about existing evidence. The original and every rejudge judgment remain recorded verbatim.
- **Not an edit.** The recorded Check Report (reasoning, assertions, judge prompts and responses) is never rewritten. Corrected tests carry their recorded result and the correction's provenance (who, when, why) alongside the effective one.
- **Not a rerun.** Execution timestamps, traces, deliverables, cost, and tokens are untouched. Schedules and webhooks are not replayed.

## Requirements

The run must be terminal with a verdict (`passed`/`failed`) and a recorded check report. Running, errored, or no-verdict runs are read-only, apo refuses with exit code `2` rather than guessing.

Corrections need human authority: a browser session member, a full-scope project API key, or open-dev mode. Ingest keys and executor credentials are refused.

## Options

| Option | Default | Description |
|---|---|---|
| `--pass` / `--fail` / `--clear` | (one required) | Set the effective result, or restore the recorded one. |
| `--reason <text>` | - | Why (required for `--pass`/`--fail`, 3–1000 chars; recorded on the correction). |
| `--task <id>` | - | Filter `last` to the latest run of a specific task. |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Correction (or idempotent re-correction) recorded. Does **not** mirror the resulting run verdict. |
| `2` | Usage error or API failure, unknown run/test, non-correctable run, bad reason, missing action flag, auth failure. |

## Examples

```bash
# A judge false-positive: the substance is there, the parenthetical wasn't
apo runs correct last "report-is-complete" --pass \
  --reason "Retention is present in the KPI table; judge missed it"

# A check that passed but shouldn't have
apo runs correct de89cab "no-failed-actions" --fail \
  --reason "The trace contains a failed payment call"

# Change your mind back to the recorded result
apo runs correct de89cab "report-is-complete" --clear
```
